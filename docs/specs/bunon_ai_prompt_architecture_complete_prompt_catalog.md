**1\. Decided Rules: Admin-Driven Prompt Architecture**

All four core architectural decisions you confirmed are locked in below. Every AI call in Bunon is assembled dynamically at runtime by the single backend AI Service Layer from database-managed prompt blocks.

**2\. The Edit, Sync & Transaction Lifecycle (Admin Screens 131, 132 & 144\)**

To make sure live users never experience a broken prompt, half-updated instruction, or slow database lookup, Bunon separates prompt management into three clean processes: the Edit & Test Process, the Atomic Transaction Process, and the Instant Cache Sync & In-Flight Safety Process.

| Process Stage | How It Works End-to-End |
| :---- | :---- |
| **A. The Edit & Test Process(Screen 131 \-\> Screen 132\)** | **1\. Never Overwrite In-Place:** In Admin Screen 132, editing an active prompt (e.g., 'v1') never mutates row 'v1'. Clicking 'Save Draft' inserts a new immutable row ('v2', 'active \= false') in 'prompt\_versions'. **2\. Automated Variable & Forbidden-Word Check: The backend verifies that all '{{variables}}' belong to that prompt's allowlist, and warns if the text accidentally contains banned words ('verified', 'signed hash', 'certificate', 'completion certificate', 'loom', 'warp', 'weft', 'sprint').** **3\. Live Sample Test (Before Publishing): Clicking 'Run Sample Test' in Screen 132 runs the draft prompt against sample user inputs using that pipeline's configured Gemini model ('system\_settings.pipeline\_models\_json': Gemini 3.5 Flash-Lite (`gemini-3.5-flash-lite`) or Gemini 3.8 Flash (`gemini-3.8-flash`) with automatic runtime normalization of legacy `2.5`/`2.0`/`1.5` model strings across Pipelines 1, 1B, and 2–7), validates the output against the locked JSON schema (passing `responseJsonSchema` only when non-empty and valid, with resilient Zod transforms for nullable strings/array bounds), and displays the exact JSON output, token count, cost (USD), and latency (ms) side-by-side.** |
| **B. The Atomic Transaction Process(Screen 132 \-\> Modal 144 \-\> DB)** | **1\. Stage & Confirm Modal (Screen 144):** Only 'SUPER\_ADMIN' can click 'Activate Version' or 'Roll Back' (for 'ADMIN', Screen 132 is read-only). Modal 144 displays 'Current Active Version (v1) \-\> New Version (v2)' with a diff view and requires typing 'CONFIRM'. **2\. Single PostgreSQL Transaction:** On confirmation, the backend runs one atomic transaction ('BEGIN ... COMMIT'):    • 'UPDATE prompt\_versions SET active \= false WHERE pipeline \= \$1 AND active \= true;'    • 'UPDATE prompt\_versions SET active \= true, activated\_at \= NOW() WHERE id \= \$2;'    • 'INSERT INTO admin\_audit\_log (admin\_id, action, target\_type, target\_id, details\_json) VALUES (...);' **3\. Zero Partial State:** Because a partial unique index ('CREATE UNIQUE INDEX one\_active\_prompt\_per\_key ON prompt\_versions (pipeline) WHERE active \= true') is enforced inside the transaction, it is mathematically impossible for a prompt key to have 0 active versions or 2 active versions at the same time. |
| **C. The Sync & In-Flight Process(DB \-\> App Cache \-\> Gemini API)** | **1\. Instant Cache Sync (Zero Redeploy):** The AI Service Layer caches active prompts in memory / Next.js cache tagged with 'active-prompts' (60s TTL fallback). Because `bunon-admin` runs as a standalone Next.js 16 project sharing the same Supabase database, `bunon` automatically picks up any activated prompt, category, or setting within its 60-second cache TTL (with optional instant cache-bust webhook support). **2\. Snapshot Isolation for In-Flight Requests:** When a user triggers an AI pipeline, the AI Service Layer loads the active prompt version snapshots at the start of the call and holds them in local memory for that request (including if the request needs its 1 automatic JSON-repair retry). If an admin activates 'v2' 500ms later, the in-flight request finishes cleanly on 'v1' and logs 'prompt\_version\_id \= v1' in 'ai\_calls'. **3\. Quality Signal Tracking per Version:** Because every row in 'ai\_calls', 'tasks', and 'milestones' links back to the 'prompt\_version\_id' that generated it, Screen 131 automatically computes quality metrics per prompt version (Task 'Not useful' rate, 'Too hard' rate, Milestone met rate, JSON retry rate). If 'v2' performs worse, SUPER\_ADMIN can click 'Roll Back to v1' in 2 seconds. |
| **E. 4-Layer Compiled Prompt Inspector & Ultimate Payload View (`/prompts/inspector`)** | **1\. Privacy-Safe Journey Simulator (8 Triggers):** Admins select any user-triggered LLM scenario (`PIPELINE_1`, `PIPELINE_1B`, `PIPELINE_2`..`PIPELINE_7`), Goal Category (`SKILL_<SLUG>`), Region (`BD` \| `GLOBAL`), Language (`EN` \| `BN`), and Active/Draft version using synthetic editable sample inputs (zero private user data). **2\. Dual Inspection Modes:** Toggle between **`'By Layer (Edit View)'`** (What Backend Pulls data map + collapsible Layers 1–4 with direct `'Edit ↗'` links) and **`'Ultimate Compiled Prompt'`** (one continuous verbatim combined payload in `'Readable Unified Text'` or `'Exact Gemini API JSON'` with char count, estimated tokens, and 1-click Copy). **3\. Live Full 4-Layer Test (`/api/admin/prompts/inspect-run`):** Fires the exact assembled 4-layer prompt to `@google/genai` (`gemini-3.5-flash-lite` / `gemini-3.8-flash`) and returns live JSON output, schema status, tokens, USD cost, and latency. |
| **D. Dynamic Category Creation & Safe Deactivation(Screen 131/132 \-\> Modal 144\)** | 1\. Create New Category ('+ Create New Category'): In Admin Screen 131, SUPER\_ADMIN clicks '+ Create New Category (Skill)' and enters: (a) Category Slug (e.g., 'LANGUAGE\_LEARNING'), (b) English & Bangla UI Labels for Screen 15 ('Language Learning' / 'ভাষা শিক্ষা'), (c) 1-line Detection Hint for Pipeline 1, (d) the 'SKILL\_\<SLUG\>' prompt instructions, and (e) optional Bangladesh Regional Context. **2\. Atomic Publish Transaction:** Confirming in Modal 144 runs a single transaction that inserts the row in 'goal\_categories', inserts and activates v1 of 'SKILL\_\<SLUG\>' in 'prompt\_versions', writes to 'admin\_audit\_log', and calls 'revalidateTag('active-prompts')'. 3\. Instant Runtime Detection & Safe Deactivation: On the very next onboarding call, the AI Service Layer queries 'goal\_categories WHERE is\_active \= true', formats '{{active\_categories\_list}}' for Pipeline 1, and populates 'responseSchema.properties.detected\_category.enum' dynamically. If a category is later deactivated ('is\_active \= false'), it stops appearing for new goals while existing goals safely retain their category or fall back to 'SKILL\_OTHER'. |

**How the AI Service Layer Assembles a Prompt at Runtime**

Every time one of the 7 AI pipelines runs, the backend AI Service Layer fetches the 4 active prompt layers from the cache and combines them in this exact order before calling Gemini with 'responseMimeType: "application/json"' and the locked 'responseSchema':

| Assembly Layer | Prompt Key(s) | What It Does at Runtime |
| :---- | :---- | :---- |
| **Layer 1: CORE System & Language** | CORE\_SYSTEM\_IDENTITY \+ CORE\_LANGUAGE\_RULES | Injected as the Gemini 'systemInstruction' on every AI call. Sets Bunon's warm, non-shaming coaching identity, plain-word rules, banned-word list, safety boundaries, and English vs. বাংলা language rules. |
| **Layer 2: SKILL (Goal-Area Skill)** | SKILL\_FITNESS \| SKILL\_WORK \| SKILL\_BUSINESS \| SKILL\_ENTREPRENEURSHIP \| SKILL\_OTHER | Selected automatically based on the goal's confirmed 'category'. Gives Gemini domain-specific rules for structuring milestones, daily output tasks, and 10-minute versions in that field. |
| **Layer 3: REGIONAL Knowledge** | REGIONAL\_BD\_CONTEXT (BD) / REGIONAL\_GLOBAL\_CONTEXT (Global fallback) | Injects real Bangladeshi context for `country = 'BD'` (BDT budgets, local platforms like bKash/Pathao/Daraz/Fiverr, university/job calendars, climate/traffic realities) and automatically falls back to `REGIONAL_GLOBAL_CONTEXT` for international users. |
| **Layer 4: PIPELINE Prompt \+ Locked Schema** | PIPELINE\_1 through PIPELINE\_7 | Injected as the user/task prompt with that pipeline's '{{variables}}' populated and its editable field descriptions merged into the locked JSON output schema. |
