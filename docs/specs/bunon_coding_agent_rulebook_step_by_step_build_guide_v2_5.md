**Bunon — Coding Agent Rulebook & Step-by-Step Build Guide (v2.5)**

Nov 16, 2026 · @Sabbir · Mandatory Architecture Standards, Folder Map & Milestone-Gated Prompt Playbook for AI Coding Agents

This rulebook is designed to be handed directly to your AI coding agent (in Cursor, Windsurf, Claude Code, or VS Code) alongside your four Version 2.5 specification files. NEVER tell an AI coding agent to 'build the whole app at once'—doing so overflows its context window and produces broken '// TODO' stubs. Instead, place all five documents in your project's '/docs/specs/' folder and instruct the agent to execute ONE milestone at a time using the exact rules and copy-paste prompts below.

**1. Golden Rules for the Coding Agent (Paste into CLAUDE.md / .cursorrules)**

Every coding agent working on the Bunon repository must obey these 8 non-negotiable engineering rules on every single file it writes:

| Engineering Rule | Exact Requirement Enforced on the Coding Agent | 
| ----- | ----- | 
| **Rule 1: Never Build Everything at Once (Milestone Lock)** | • Work strictly on the current milestone requested by the user. • Do NOT generate placeholder pages for future milestones. • At the end of each milestone, run 'npm run typecheck' and 'npm run build' and fix all TypeScript errors before stopping. | 
| **Rule 2: Zero '// TODO' or Fake Mock Data** | • Strictly FORBID '// TODO', '// implement later', or hardcoded fake arrays in production routes. • Every API route and server action must read and write real rows in Supabase PostgreSQL. | 
| **Rule 3: Mandatory Top-of-File Header Comment** | • Every '.ts' and '.tsx' file MUST start with a 4-line header comment stating:   (1) Purpose of the file in plain English,   (2) Spec Reference (e.g., 'UI Guide Screen 22 & 50a | 
| **Rule 4: 250-Line Maximum File Size (Modular Split)** | • Never write 800-line spaghetti files. Keep every component and service file under 250 lines. • Split UI into clean sub-components ('TaskCard.tsx', 'SubStepList.tsx', 'UndoChip.tsx') and keep all database/AI logic inside 'src/lib/'. | 
| **Rule 5: Server-Only Secrets & 4-Gate AI Firewall** | • Import 'server-only' at the top of 'src/lib/ai/\*' and 'src/lib/db/admin.ts'. • The browser client can NEVER call Gemini directly or read system tables ('prompt_versions', 'ai_calls', 'system_settings'). Every AI call must pass through 'src/lib/ai/firewall.ts'. | 
| **Rule 6: Strict TypeScript & Locked JSON Schemas** | • Enable '"strict": true' in 'tsconfig.json'. Never use 'any'. • Define Zod / TypeScript interfaces in 'src/types/' matching the exact Locked Output JSON Keys in 'Bunon — AI Prompt Architecture & Complete Prompt Catalog (v2.5)'. | 
| **Rule 7: Enforce Bunon's 99% Neutral + 1% Marigold UI** | • Follow Section 1 of the Stitch UI Design Guide strictly: '#F6F7F8' page bg, '#FFFFFF' cards, '1px solid #E3E5E8' borders, zero drop shadows on cards, strictly ONE solid black button ('#1A1A1B') per screen, and Marigold ('#FFB020') ONLY on finished marks. | 
| **Rule 8: Exact v2.5 Behavioral Contracts (Zero Blackbox)** | • Completion-Gated Weeks: In 'deliverable_queue', never close a week until all deliverables are 'DONE' or 'SKIPPED_BASIC'. • Sub-Steps: Steps 1..N-1 tick with 0 proof; Final Step N shows 'Add proof' + Camera + Note and completes the mother task. • Day Notes: Save at \$0 tokens after a 0ms crisis regex check; never trigger an immediate LLM call. • Frictionless Auth & Entry Flow: `/` and `/today` allow Direct Guest Entry (clean empty state with `'Start your first goal'` CTA -> `/login?next=/onboarding` and subtle `'Sign in'` header link); `/login` uses Email + Password (min 8 chars) via `supabase.auth.signUp` / `signInWithPassword` with no repeated OTPs and standard email-link password reset; never force 0-goal authenticated users into `/onboarding`; automatically upsert `public.users` on first authenticated session so profile updates never fail with `401`. |

**3. How to Prepare Your Workspace Before Prompting the Agent**

Before you send your first prompt to the coding agent, take 5 minutes to set up your project folder cleanly so the agent can read your specifications directly from disk:

* **Step 1 — Convert or Copy the Spec Text into Markdown:** Most coding agents (Cursor, Windsurf, Claude Code) read '.md' files much faster and more accurately than binary '.docx' files. Place the 4 updated '.docx' files in 'docs/specs/' AND ask the agent in Step 0 to convert them to 'docs/specs/01-ui-guide.md', '02-database-schema.md', '03-prompt-catalog.md', and '04-master-plan.md' using 'python-docx' or 'pandoc' so it can grep them anytime.

* **Step 2 — Save Section 1 & 2 of This Rulebook as CLAUDE.md / .cursorrules:** Create a file named 'CLAUDE.md' (and '.cursorrules') in the root of your repository containing the 8 Golden Rules and the Folder Map from Sections 1 and 2 above. Coding agents automatically read that file on every turn.

* **Step 3 — Execute Strictly One Milestone Prompt at a Time:** Use the 7 copy-paste prompts in Section 4 below in order. After each milestone finishes, test it in your browser at 'http://localhost:3000' before pasting the next milestone prompt.
