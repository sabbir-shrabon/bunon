**Bunon — Coding Agent Rulebook & Step-by-Step Build Guide (v2.5)**

Nov 24, 2026 · @Sabbir · Synchronized v2.5+ Architecture Standards (Next.js 16 `proxy.ts` + Tailwind v4 + `sin1`), Folder Map (`src/lib/services/` & `mcp/`), Standalone `bunon-admin`, & Milestone-Gated Prompt Playbook

This rulebook is designed to be handed directly to your AI coding agent (in Cursor, Windsurf, Claude Code, or VS Code) alongside your four Version 2.5 specification files. NEVER tell an AI coding agent to 'build the whole app at once'—doing so overflows its context window and produces broken '// TODO' stubs. Instead, place all five documents in your project's '/docs/specs/' folder and instruct the agent to execute ONE milestone at a time using the exact rules and copy-paste prompts below.

**1. Golden Rules for the Coding Agent (Paste into CLAUDE.md / .cursorrules)**

Every coding agent working on the Bunon repository must obey these 8 non-negotiable engineering rules on every single file it writes:

| Engineering Rule | Exact Requirement Enforced on the Coding Agent | 
| ----- | ----- |

| **Rule 2: Zero '// TODO' or Fake Mock Data** | • Strictly FORBID '// TODO', '// implement later', or hardcoded fake arrays in production routes. • Every API route and server action must read and write real rows in Supabase PostgreSQL. |

| **Rule 5: Server-Only Secrets & 4-Gate AI Firewall** | • Import 'server-only' at the top of 'src/lib/ai/\*' and 'src/lib/db/admin.ts'. • The browser client can NEVER call Gemini directly or read system tables ('prompt_versions', 'ai_calls', 'system_settings'). | **Rule 10: Next.js 16, Tailwind v4 & Anti-Phishing Hardening** | • Use `src/proxy.ts` (never deprecated `middleware.ts`) with 0ms guest fast-path (`sb-*` cookie check) and HTTP `404` on `/admin*`. • Call `await connection()` inside `<Suspense>` on dynamic Server Components. • Use `@custom-variant dark (&:where(.dark, .dark *));` and `@layer base` resets in `globals.css`. • Enforce `sanitizeRedirect()` on `?next=`, `safeExternalUrl()` on proof links, and `X-Frame-Options: DENY` / `X-Content-Type-Options: nosniff` / `Referrer-Policy` headers. • Use live `gemini-3.5-flash-lite` / `gemini-3.8-flash` (with legacy `2.5` auto-normalization). |

**3. How to Prepare Your Workspace Before Prompting the Agent**

Before you send your first prompt to the coding agent, take 5 minutes to set up your project folder cleanly so the agent can read your specifications directly from disk:

* **Step 1 — Convert or Copy the Spec Text into Markdown:** Most coding agents (Cursor, Windsurf, Claude Code) read '.md' files much faster and more accurately than binary '.docx' files. Place the 4 updated '.docx' files in 'docs/specs/' AND ask the agent in Step 0 to convert them to 'docs/specs/01-ui-guide.md', '02-database-schema.md', '03-prompt-catalog.md', and '04-master-plan.md' using 'python-docx' or 'pandoc' so it can grep them anytime.

* **Step 2 — Save Section 1 & 2 of This Rulebook as CLAUDE.md / .cursorrules:** Create a file named 'CLAUDE.md' (and '.cursorrules') in the root of your repository containing the 8 Golden Rules and the Folder Map from Sections 1 and 2 above. Coding agents automatically read that file on every turn.

* **Step 3 — Execute Strictly One Milestone Prompt at a Time:** Use the 7 copy-paste prompts in Section 4 below in order. After each milestone finishes, test it in your browser at 'http://localhost:3000' before pasting the next milestone prompt.
